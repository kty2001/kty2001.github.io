이번 주 학습 내용

지난주에 HTML과 CSS로 화면의 뼈대를 쌓았다면, 이번 주 초반 이틀은 그 화면을 움직이게 하는 JavaScript였다. 문법을 먼저 훑고, DOM을 고르고 바꾸는 법, 이벤트, 그리고 비동기 요청까지 이어갔다. 수요일부터는 반대편으로 넘어가 화면을 서버에서 만들어 내려주는 Django를 시작했다. 프로젝트 구조, 템플릿, ORM을 하루씩 쌓고, 마지막 날에는 그걸 전부 합친 QnA 게시판 코드를 따라가봤다. 앞에서 배운 fetch가 게시판의 추천 버튼과 아이디 중복 확인에서 다시 등장하면서, 한 주 동안 배운 두 덩어리가 하나로 이어졌다.

01. JavaScript 기본기 — 자료형, 형변환, 단축평가

자료형은 undefined, string, number, boolean, null, object, bigint, symbol 여덟 가지다. 배열과 함수도 typeof로 찍어보면 결국 object 계열로 묶인다. 변수는 let, 상수는 const로 선언하고, var는 예전 코드 호환용이라 쓰지 않는다. var는 if/for 블럭을 무시하고 함수 단위로만 범위가 잡혀서, 블럭 안에서 선언한 값이 밖으로 새어 나온다.

제일 헷갈렸던 건 암묵적 형변환이었다. 같은 문자열 "3"인데 연산자에 따라 결과가 달라진다.

console.log(3 + "3"); // "33" — +는 문자열 이어붙이기가 우선 console.log(3 - "3"); // 0 — 나머지 산술은 숫자로 변환 console.log(3 - "a"); // NaN console.log(3 == "3"); // true — 형변환 후 비교 console.log(3 === "3"); // false — 타입까지 같아야 true Boolean([]); // true — 빈 배열·빈 객체도 truthy Boolean(''); // false — 0, '', null, undefined, NaN은 falsy

그래서 비교는 되도록 ===를 쓰라는 이야기를 들었다. 숫자 변환도 방법마다 달라서, '123.456원'은 Number()로는 NaN이지만 parseInt()는 앞에서부터 읽을 수 있는 데까지 읽어 123을 돌려준다.

truthy/falsy를 알고 나니 단축평가가 자연스럽게 이해됐다. ||는 앞이 참이면 뒤를 보지 않고, &&는 앞이 거짓이면 뒤를 보지 않는다. 이걸 이용해 Number(answer) || 1000처럼 기본값을 주거나, user?.username 같은 옵셔널 체이닝으로 객체가 없을 때 에러 대신 undefined를 받을 수 있다.

02. 함수와 객체 — 화살표 함수, 1급 객체, class, 구조분해

함수는 선언식과 표현식 두 가지로 만든다. 선언식은 호이스팅되어 선언보다 위에서 호출해도 동작하지만, 변수에 담은 표현식은 그렇지 않다. 짧게 쓸 때는 화살표 함수 (a, b) => a + b를 쓴다. ...은 자리에 따라 뜻이 갈렸다. 매개변수 자리에서는 남은 인자를 배열로 묶는 나머지 파라미터, 호출하는 자리에서는 배열을 펼치는 전개 연산자다.

함수를 변수에 담고, 배열에 넣고, 인자로 넘기고, 리턴값으로 돌려줄 수 있다는 게 1급 객체라는 뜻이었다. 함수를 돌려주는 함수는 꽤 재미있었다.

const getDessert = (dessert) => (name) => `${name}이/가 ${dessert} 먹음`; const getCake = getDessert('🎂'); const getDonut = getDessert('🍩'); console.log(getCake('철수')); // 철수이/가 🎂 먹음 console.log(getDonut('은희')); // 은희이/가 🍩 먹음

getCake는 만들어질 때 받은 '🎂'를 계속 기억하고 있다. 같은 틀에서 디저트만 바꾼 함수를 여러 개 찍어낼 수 있는 구조다.

객체 쪽은 prototype에서 시작했다. 생성자 함수로 객체를 만들면 그 객체의 __proto__가 Pet.prototype을 가리키고, 여기에 메소드를 달아두면 모든 객체가 같이 쓴다. 거슬러 올라가면 끝에는 Object.prototype이 있어서, 정의한 적 없는 toString()도 호출된다. class는 이 구조를 더 읽기 쉽게 쓰는 문법이라, constructor, static, extends와 super로 같은 내용을 다시 작성해봤다.

const user = { id: 'honggd', name: { firstName: '길동', lastName: '홍' }, sns: ['tiktok', 'thread', 'X'] }; // 중첩 객체와 배열을 한 번에 꺼내기 const { id, name: { firstName }, sns: [mainSns] } = user; // 매개변수 자리에서 바로 분해 const handleId = ({ id }) => console.log(id);

구조분해 할당은 배열은 순서로, 객체는 속성 이름으로 값을 꺼낸다. 처음엔 문법이 낯설었는데, 뒤에서 fetch 응답을 받을 때 const {id, company} = data처럼 계속 쓰여서 금방 손에 익었다.

03. DOM — 요소를 고르고, 따라가고, 바꾸기

브라우저는 HTML을 읽어 DOM 트리를 만들고, JavaScript는 이 트리의 노드를 객체로 다룬다. 고르는 방법은 getElementById, getElementsByClassName 같은 옛 방식과 CSS 선택자를 그대로 쓰는 querySelector / querySelectorAll이 있다. 지난주에 배운 선택자가 여기서 그대로 쓰였다. 태그 객체를 담는 변수에는 $sample처럼 $를 붙여 구분하는 습관도 같이 배웠다.

  • 탐색 — children, parentElement, nextElementSibling처럼 Element 전용 속성을 쓰면 줄바꿈 텍스트 노드에 걸리지 않는다
  • 유사 배열 — children이 돌려주는 HTMLCollection은 forEach가 없어서 Array.from()이나 [...]로 진짜 배열로 바꿔 쓴다
  • 스타일 — style.backgroundColor는 인라인 스타일을 직접 바꾸고, classList.add/remove는 미리 만든 CSS 클래스를 붙였다 뗀다
  • 내용 — innerHTML은 태그를 해석하고, innerText는 태그까지 글자 그대로 넣는다
// 기준 요소의 앞·안쪽 처음·안쪽 끝·뒤에 끼워 넣기 $target.insertAdjacentHTML('beforebegin', '<span>🎈</span>'); $target.insertAdjacentHTML('afterbegin', '<span>🎈</span>'); $target.insertAdjacentHTML('beforeend', '<span>🎈</span>'); $target.insertAdjacentHTML('afterend', '<span>🎈</span>'); // 객체로 만들어 붙이기 const $h3 = document.createElement('h3'); $h3.appendChild(document.createTextNode('안녕, HTML')); document.querySelector('#area').appendChild($h3);

이미 화면에 있는 요소를 appendChild로 다른 부모에 붙이면 복사가 아니라 이동이 된다는 것도 해보고 나서야 알았다. 삭제는 remove()로 자기 자신을, innerHTML = ''로 자식 전체를 지운다. 그 밖에 window가 탭마다 하나씩 있는 최상위 객체이고, 그 아래 document(DOM)와 location, history, navigator, screen(BOM)이 달려 있다는 구조도 정리했다. setInterval로 1초마다 시각을 갱신하는 시계도 하나 만들어봤다.

04. 이벤트 — 클릭, 입력, 제출, 그리고 전파

이벤트는 onclick 속성이나 addEventListener로 연결한다. onclick은 하나만 들어가서 다시 대입하면 덮어쓰지만, addEventListener는 같은 이벤트에 핸들러를 여러 개 걸 수 있다. 입력창에는 focus/blur, 키보드에는 keydown/keyup을 붙여봤고, 한글처럼 조합해서 입력하는 글자는 조합이 끝났을 때 compositionend가 따로 발생한다는 것도 봤다.

가장 실용적이었던 건 폼 제출 전 검사였다.

$frm.onsubmit = (e) => { if (!/^[a-zA-Z0-9]{4,}$/.test($username.value)) { alert('아이디 영문자/숫자 4글자 이상 입력해주세요.'); e.preventDefault(); // 서버로 보내지 않음 return; } if ($password.value !== $confirmPassword.value) { alert('두 비밀번호가 일치하지 않습니다.'); e.preventDefault(); $password.select(); return; } };

submit 버튼을 누르면 submit 이벤트 → 핸들러 → 실제 제출 순서로 흘러가기 때문에, 중간에서 preventDefault()로 막을 수 있다. 형식 검사는 정규표현식 test()로 했다.

이벤트 전파도 직접 확인했다. div 세 개를 겹쳐놓고 가장 안쪽을 누르면 바깥 div와 body의 핸들러까지 차례로 실행된다(버블링). 중간에서 e.stopPropagation()을 부르면 거기서 멈춘다. 반대로 이 성질을 이용하면 바깥 요소 하나에만 핸들러를 달고 e.target.id로 실제 눌린 요소를 구분할 수도 있다.

05. 비동기 — 콜백에서 Promise, fetch까지

JavaScript는 한 번에 한 가지 일만 하는데, 기다려야 하는 작업은 Web API에 맡겨두고 다음 줄로 넘어간다. 때가 되면 콜백이 대기열에 들어가고, 실행 중인 코드가 비면 이벤트 루프가 꺼내서 실행한다. 그래서 아래 코드는 undefined가 먼저 찍힌다.

let value2; setTimeout(() => { value2 = 200; console.log(value2); // 1초 뒤 200 }, 1000); console.log(value2); // 바로 undefined

박스 색을 1초 간격으로 일곱 번 바꾸는 예제를 콜백으로 짜니 setTimeout이 여섯 겹으로 파고들었다. 같은 동작을 Promise로 바꾸면 한 줄씩 아래로 늘어선다. then이 다시 Promise를 돌려주기 때문에 이어 붙일 수 있는 구조다.

const changeBGColor = (color, millis) => new Promise((resolve) => { setTimeout(() => { $box.style.backgroundColor = color; resolve(); }, millis); }); changeBGColor('orange', 1000) .then(() => changeBGColor('yellow', 1000)) .then(() => changeBGColor('green', 1000));

Promise는 처음에 pending이고, resolve가 불리면 fulfilled, reject가 불리면 rejected가 된다. 네트워크 요청을 보내는 fetch도 Promise를 돌려준다. GitHub API로 내 프로필 이미지 주소를 받아와 img 태그로 붙이고, 같은 요청을 axios로도 보내봤다. axios는 응답을 JSON으로 바꾸는 단계를 대신 해줘서 .then(({data}) => ...)로 바로 꺼낼 수 있었다. async/await는 실습 페이지만 만들어두고 진도가 Django로 넘어갔는데, 금요일 게시판 코드에서 실제로 쓰이는 걸 보게 됐다.

06. Django 첫 프로젝트 — 프로젝트와 앱, URL과 View

Django는 프로젝트(설정 전체) 안에 기능별 앱을 여러 개 두는 구조다. startproject로 만든 _01_django_project 폴더에 설정이 들어 있고, startapp으로 만든 first, second가 각각의 기능을 맡는다. 요청이 들어오면 프로젝트의 urls.py가 경로를 보고 앱의 urls.py로 넘기고, 거기서 연결된 view 함수가 응답을 만든다.

# 프로젝트 urls.py urlpatterns = [ path('admin/', admin.site.urls), path('', RedirectView.as_view(url='/first/', permanent=False)), path('first/', include('first.urls')), path('second/', include('second.urls')), ] # first/urls.py app_name = 'first' urlpatterns = [ path('', views.index, name='index'), path('home', views.home, name='home'), ] # first/views.py def index(request): return HttpResponse('Hello django') def home(request): return render(request, 'first/home.html')

view는 request를 받아 응답을 돌려주는 함수다. 글자만 돌려줄 때는 HttpResponse, HTML 파일을 쓸 때는 render를 쓴다. 템플릿 폴더는 settings.py의 TEMPLATES['DIRS']에 BASE_DIR / 'templates'로 등록하고, 앱 이름으로 하위 폴더를 나눠 같은 이름의 파일이 섞이지 않게 했다.

07. Django 템플릿 — 변수, 태그, 상속, 정적 파일, URL

템플릿은 HTML 안에 {{ }}로 값을, {% %}로 로직을 넣는다. view에서 넘긴 딕셔너리의 키가 그대로 변수 이름이 된다. 값 뒤에 |를 붙이면 필터로 후처리할 수 있다.

<p>제 이름은 {{ name | upper }}입니다. 저는 {{ age | add:1 }}살입니다.</p> <p>오늘은 {{ today | date:"Y/m/d (D) H:i:s" }}입니다.</p> {% for user in users %} <tr> <td>{{ forloop.counter }}</td> <td>{{ user.name }}</td> </tr> {% empty %} <tr><th colspan="5">조회된 회원이 없습니다.</th></tr> {% endfor %}

{% for %}에는 목록이 비었을 때를 위한 {% empty %}와 몇 번째 반복인지 알려주는 forloop.counter가 있다. {% with %}로 만든 변수는 {% endwith %}까지만 살아 있어서, 블럭 밖에서 같은 변수를 찍으면 빈칸이 나왔다.

  • 레이아웃 — base.html에 {% block content %} 자리를 비워두고, 각 페이지는 {% extends %}로 상속해 그 자리만 채운다. 헤더·푸터는 {% include %}로 끼워 넣는다
  • 정적 파일 — STATICFILES_DIRS에 static 폴더를 등록하고, 템플릿 맨 위에 {% load static %}를 쓴 뒤 {% static 'css/global.css' %}로 경로를 만든다
  • URL — 주소를 직접 적지 않고 {% url 'app:articles_detail' id=1 %}처럼 이름으로 만든다. 경로를 바꿔도 템플릿을 고칠 필요가 없다
path('articles_category/<str:category>/<int:id>', views.articles_category, ...) def search(request): q = request.GET.getlist('q', []) # ?q=로션&q=치약 → ['로션', '치약'] lang = request.GET.get('lang', '') return render(request, 'app/05_urls.html', {'q': q, 'lang': lang})

값을 넘기는 방법은 두 가지다. 경로 안에 <int:id>로 박아두면 view의 매개변수로 들어오고, ?q=... 쿼리스트링은 request.GET으로 꺼낸다. 같은 키가 여러 번 오면 get은 마지막 하나만, getlist는 전부를 준다. 마지막에는 Bootstrap CDN을 붙여 미리 만들어진 클래스로 화면을 꾸며봤다.

08. Django ORM — 테이블을 클래스로, SQL을 메소드로

ORM은 테이블을 파이썬 클래스로 정의하고, SQL 대신 메소드로 데이터를 다루게 해준다. DB는 MySQL로 바꿨다. django 계정과 djangodb 데이터베이스를 만들고, 한글과 이모지를 담기 위해 utf8mb4로 설정했다.

class Product(models.Model): name = models.CharField(max_length=100) price = models.PositiveIntegerField() stock = models.PositiveIntegerField() created_at = models.DateTimeField(auto_now_add=True) # 처음 저장할 때만 updated_at = models.DateTimeField(auto_now=True) # 저장할 때마다 class Discount(models.Model): # 1:1 product = models.OneToOneField(Product, on_delete=models.CASCADE) class Review(models.Model): # 1:N product = models.ForeignKey(Product, on_delete=models.CASCADE, related_name='reviews') class Category(models.Model): # N:M products = models.ManyToManyField(Product, related_name='categories')

모델을 고친 뒤 makemigrations로 변경 기록 파일을 만들고, migrate로 실제 DB에 반영한다. related_name을 정해두면 반대 방향에서도 product.reviews.all()처럼 접근할 수 있다.

조회는 manage.py shell에서 직접 쳐봤다. filter는 여러 행을 QuerySet으로, get은 정확히 한 행만 돌려주고 없거나 여러 개면 에러가 난다. 조건은 필드 이름 뒤에 밑줄 두 개로 붙인다.

product.reviews.filter(rating__gte=4) # 4점 이상 Review.objects.filter(created_at__range=(start, end)) # 기간 Product.objects.filter(categories__isnull=True) # 카테고리 없는 상품 # 한 상품의 평균 평점 → 값 하나 product.reviews.aggregate(avg_rating=Avg('rating')) # 모든 상품에 평균 평점·리뷰 수 컬럼을 붙여서 → 상품 목록 Product.objects.annotate(avg_rating=Avg('reviews__rating'), review_count=Count('reviews'))

aggregate는 전체를 하나의 값으로 모으고, annotate는 각 행에 계산한 값을 붙인다. 그리고 반복문 안에서 연관 객체를 꺼낼 때마다 쿼리가 한 번씩 더 나가는 N+1 문제도 들었다. 1:1이나 FK처럼 하나를 따라가는 관계는 select_related로 JOIN해서 한 번에, 역참조나 N:M처럼 여러 개를 가져오는 관계는 prefetch_related로 미리 모아서 가져온다.

09. QnA 게시판 — 지금까지 배운 걸 한 프로젝트로

금요일에는 질문·답변 게시판 04_qna를 따라갔다. 게시판 기능을 맡는 qna 앱과 회원 기능을 맡는 uauth 앱 두 개로 나뉘어 있다. 질문(Question)과 답변(Answer)은 FK로 이어지고, 작성자는 Django 기본 User를 FK로, 추천한 사람 목록은 User와의 N:M으로 둔다. 화면은 Bootstrap을 붙인 base.html을 상속해서 만들었다.

@login_required(login_url='uauth:login') def question_create(request): if request.method == 'POST': form = QuestionForm(request.POST) if form.is_valid(): question = form.save(commit=False) # 아직 DB에 저장하지 않음 question.author = request.user # 작성자를 채운 뒤 question.save() # 저장 return redirect('qna:question_detail', question_id=question.id) else: form = QuestionForm() return render(request, 'qna/question_form.html', {'form': form})

하나의 view가 GET이면 빈 폼을 보여주고 POST면 저장하는 구조다. ModelForm은 모델을 바탕으로 입력 검사(is_valid)까지 해준다. 폼에 없는 작성자 값은 commit=False로 저장을 잠시 미뤄두고 채워 넣는다. 저장한 뒤에는 화면을 바로 그리지 않고 redirect로 상세 페이지로 보낸다. 새로고침했을 때 POST가 다시 전송되는 걸 막기 위해서다.

  • 권한 — @login_required로 로그인을 강제하고, 수정·삭제는 request.user != question.author and not request.user.is_staff로 한 번 더 막는다
  • 목록 — Paginator(questions, 10)로 10개씩 자르고, 템플릿에서는 현재 페이지 앞뒤 3개 번호만 보여준다. 쿼리에는 select_related('author')와 prefetch_related('answer_set')를 붙였다
  • 알림 — messages.error(), messages.success()로 남긴 메시지를 base.html에서 Bootstrap alert로 띄운다
  • 회원가입 — UserCreationForm을 상속해 생일·프로필 이미지를 추가했다. 이 두 값은 User와 1:1인 UserDetail에 저장하고, 두 테이블 저장은 transaction.atomic()으로 묶어 한쪽만 들어가는 일이 없게 했다

가장 반가웠던 건 앞에서 배운 JavaScript가 여기서 다시 나온 부분이다. 추천 버튼을 누르면 페이지를 새로 불러오지 않고 숫자만 바뀐다.

$tag.addEventListener('click', async (e) => { const response = await fetch($tag.dataset.uri, { method: 'POST', headers: { 'X-CSRFToken': '{{ csrf_token }}' } }); const data = await response.json(); if (data.result == 'success') { $tag.querySelector('span').textContent = data.vote_count; } else { alert(data.message); // 본인 글 추천 시 } });
def question_vote(request, question_id): question = Question.objects.get(id=question_id) if question.voters.filter(id=request.user.id).exists(): question.voters.remove(request.user) # 이미 추천했으면 취소 else: question.voters.add(request.user) return JsonResponse({'result': 'success', 'vote_count': question.voters.count()})

서버는 HTML 대신 JsonResponse로 숫자만 돌려주고, 브라우저는 await로 그걸 받아 DOM의 숫자만 바꾼다. 요청 URL은 템플릿의 data-uri 속성에 {% url %}로 미리 박아두고 dataset.uri로 꺼낸다. Django는 POST 요청마다 CSRF 토큰을 검사하기 때문에, 폼에서는 {% csrf_token %}을, fetch에서는 X-CSRFToken 헤더를 넣어야 한다. 회원가입의 아이디 중복 확인도 같은 방식이었다. 입력할 때마다 check_username에 GET 요청을 보내고, 받은 {available, message}를 구조분해해서 입력창 아래 문구를 바꾼다.

답변 수정에 별도 페이지가 없는 이유도 여기서 보였다. 수정 버튼에 data-answer-id와 data-answer-content를 달아두고, 클릭하면 JavaScript가 Bootstrap 모달 안의 textarea와 폼 action을 채운다. 그래서 answer_modify view는 POST만 처리하면 된다.

Keep

지난주 목표였던 "HTML·CSS 페이지에 동작 붙이기"를 그대로 이어갔다. DOM과 이벤트를 배우고 나니 지난주에 만든 화면이 버튼 하나, 입력창 하나 단위로 다르게 보였다. 그리고 금요일 QnA 코드를 읽을 때 월·화에 배운 fetch, 구조분해, dataset, 이벤트 핸들러가 전부 다시 나와서, 따로 배운 내용이 실제로 어디에 쓰이는지 확인할 수 있었다.

Problem

진도가 빨라서 직접 쳐보는 양이 줄었다. JavaScript는 이틀 만에 문법부터 비동기까지 지나갔고, async/await 실습 파일은 HTML만 만들어두고 비어 있다. ORM 실습 문제 20개도 주석만 적어놓고 풀지 못했다. 게시판 코드는 따라 읽기는 했지만 처음부터 혼자 짜라고 하면 어디서 막힐지 모르겠다. 지난주 Try였던 DVC 원격 저장소 연결과 미뤄둔 이미지 모델 서빙·동영상 RAG도 이번 주 역시 손을 대지 못했다.

Try

비어 있는 12_async_await.js부터 채우고, 앞에서 Promise로 짠 색 바꾸기와 fetch 예제를 async/await로 다시 써볼 생각이다. ORM 실습 문제 20개는 shell에서 하나씩 풀면서 connection.queries로 실제 SQL도 같이 확인하려 한다. QnA 게시판은 코드를 보지 않고 질문 CRUD까지만이라도 직접 다시 만들어볼 계획이다.

새롭게 발견한 것

받아온 프로젝트에는 manage.py가 없었다. 수업 저장소에서 04_qna를 내려받아보니 manage.py와 migrations 폴더가 빠져 있었다. .gitignore를 열어보니 둘 다 제외 대상으로 적혀 있었다. 받아서 바로 runserver를 할 수 있는 상태가 아니라, manage.py를 다시 만들고 makemigrations부터 돌려야 하는 구조였다. 반대로 내 로컬 실습 폴더에는 db.sqlite3와 마이그레이션 파일이 그대로 쌓여 있었다. 무엇을 저장소에 올리고 무엇을 각자 만들게 할지는 .gitignore가 정한다는 걸 다시 느꼈다.

확장자 없는 djangodb 파일의 정체. ORM 실습 폴더에 djangodb라는 정체 모를 파일이 있었다. 열어보니 SQLite 데이터베이스였고, 안에는 auth_user 같은 Django 기본 테이블이 들어 있었다. 아마 DATABASES의 NAME만 'djangodb'로 바꾸고 ENGINE은 아직 sqlite3인 상태에서 migrate를 한 번 돌렸던 흔적 같다. SQLite 엔진에서는 NAME이 DB 이름이 아니라 파일 경로라서, 그 이름으로 파일이 하나 생긴 것이다.

f-string 안에 같은 따옴표를 또 쓸 수 있다. 게시판 view에 f"{resolve_url("qna:question_detail", question_id=question_id)}#answer_{answer.id}"처럼 큰따옴표 안에 큰따옴표가 들어간 줄이 있었다. 당연히 문법 에러일 줄 알았는데, 파이썬 3.12부터는 f-string 안의 중괄호에서 바깥과 같은 따옴표를 다시 쓸 수 있게 바뀌었다고 한다. 다만 이전 버전에서는 에러가 나니, 다른 환경에서 돌릴 코드라면 안쪽은 작은따옴표로 바꿔 쓰는 게 안전하다.

트러블슈팅

문제 : 상품을 조회하면 AttributeError가 났다

shell에서 Product.objects.get(id=1)을 치거나 리뷰를 출력하면 결과 대신 에러가 났다.

AttributeError: 'Product' object has no attribute 'title'

Product에는 title 필드가 없는데 왜 찾는지 의아했다. 원인은 __str__이었다. Post 모델을 만들 때 쓴 return self.title을 그대로 복사해 와서, 상품명 필드 name 대신 없는 title을 찾고 있었다. shell은 객체를 화면에 보여줄 때 __str__을 부르기 때문에, 조회 자체는 성공했는데 출력하는 순간 터진 것이다. 리뷰 목록을 찍을 때도 review.product를 같이 출력하는 순간 같은 에러가 났다.

def __str__(self): return self.title # 수정 전 — Post에서 복사 def __str__(self): return self.name # 수정 후

__str__은 DB 컬럼과 상관없는 메소드라서 makemigrations나 migrate 단계에서는 아무 경고도 나오지 않는다. 모델을 복사해서 만들 때는 필드뿐 아니라 메소드 안에서 쓰는 이름까지 같이 확인해야 한다는 걸 배웠다.

문제 : 모든 상품의 평균 평점을 구하는 annotate에서 FieldError가 났다

상품별 평균 평점과 리뷰 수를 한 번에 붙이려고 annotate를 썼는데 바로 에러가 났다.

Product.objects.annotate( average_rating = Avg('reviews_rating'), # 밑줄 하나 review_count = Count('reviews') ) # FieldError: Cannot resolve keyword 'reviews_rating' into field.

관계를 건너가 다른 모델의 필드를 가리킬 때는 reviews__rating처럼 밑줄을 두 개 써야 한다. 밑줄 하나면 Django는 reviews_rating이라는 필드를 찾다가 없다고 판단한다. rating__gte, created_at__range처럼 조건을 붙일 때 쓰던 그 밑줄 두 개가 관계를 따라갈 때도 똑같이 쓰인다.

고치고 나니 이번엔 반복문에서 AttributeError가 났다. annotate에서는 average_rating으로 이름을 붙여놓고, 출력할 때는 product.avg_rating, 심지어 한 곳은 product.avg_raing으로 꺼내고 있었다.

products = Product.objects.annotate( avg_rating = Avg('reviews__rating'), review_count = Count('reviews') ) for product in products: avg_rating = f'{product.avg_rating:.2f}' if product.avg_rating else '0'

annotate에 준 키워드가 그대로 객체의 속성 이름이 되니, 붙일 때와 꺼낼 때 같은 이름을 써야 한다. 리뷰가 없는 상품은 평균이 None으로 나와서 :.2f 포맷이 실패하기 때문에, 앞에 조건을 둬 '0'으로 바꿔주는 처리도 필요했다.

문제 : 시계가 10초에 "010"으로 표시됐다

1초마다 시:분:초를 갱신하는 시계를 만들었는데, 가끔 세 자리가 찍혔다. 10시, 10분, 10초가 되는 순간에만 010으로 나왔다.

const f = (n) => n > 10 ? n : '0' + n; // 수정 전

한 자리 숫자 앞에 0을 붙이려던 함수인데, 조건이 n > 10이라 10은 "10보다 크다"에 해당하지 않는다. 그래서 10도 한 자리로 취급돼 앞에 0이 붙었다. 0~9만 걸러야 하니 기준을 뒤집어야 했다.

const f = (n) => n < 10 ? '0' + n : n; // 수정 후 const f2 = (n) => String(n).padStart(2, '0'); // 내장 메소드로

문자열의 padStart(2, '0')를 쓰면 길이가 2가 될 때까지 앞에 0을 채워줘서 경계값을 고민할 필요가 없다. 1초마다 바뀌는 화면이라 대부분의 시간에는 멀쩡해 보여서 더 늦게 눈에 띄었다. 조건문은 경계값 하나만 넣어봐도 바로 확인된다는 걸 다시 배웠다.
